# Проверяющим: кейс 8 за 5–7 минут

1. Выполните быстрый запуск из README и создайте администратора. Откройте localhost:8080.
2. В «Источниках» дождитесь готовности базы знаний и Prometheus online. Нажмите «Аварийные события»; обновление занимает до 30 секунд.
3. В «Событиях» откройте PostgreSQL или Nginx. Проверьте тип, категорию, приоритет, объяснение и рекомендованный регламент с источником.
4. Нажмите «Принято к ручному выполнению», затем «Выполнено вручную». Проверьте «Журнал действий». Инфраструктурные команды приложение не запускает.
5. В «Базе знаний» загрузите examples/reviewer-queue.json. Дождитесь завершения задания. Найдите: «Заказы стоят, обработчик не забирает сообщения». Ожидается инструкция «Очередь заказов Маяк не обрабатывается» с шагами и предостережением.
6. В «Источниках» нажмите «Восстановление». Дождитесь изменения событий, проверьте сохранение ручной истории.
7. Для проверки большого файла используйте HTTP smoke: он создаёт PDF на 60 страниц и проверяет фоновый импорт без ожидания в HTTP-соединении.

## Что сдаётся
Кейс 8: ИИ-ассистент дежурного. Интеграция с одним Prometheus удовлетворяет требованию «Zabbix или Prometheus». Учебный exporter меняет синтетические метрики, настоящий Prometheus формирует alerts, приложение читает их через API.

Видео команды: media/deykstra-demo.mp4. Метрики и границы проверки: submission-verification.md. Основной способ проверки — полный Compose; состояние публичного стенда указано в README.

На новом компьютере модель скачивается один раз. Размещение на localhost доступно только с этого компьютера; это не публичная ссылка.

## Автоматические проверки
```bash
docker compose --profile test run --build --rm tests
docker compose --profile test run --rm --no-deps tests python scripts/evaluate.py --output /tmp/classification.json
```
HTTP и браузерные проверки используют E2E_EMAIL/E2E_PASSWORD выделенного тестового пользователя. Не запускайте их на рабочей базе: они создают инструкции и ручные действия.
