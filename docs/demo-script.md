# Демонстрация «Сигналиса» — 5–7 минут

Демонстрируйте локальный комплект, а не прежний публичный сайт. Подготовка и статус проверки — в `final-readiness.md`.
Используйте отдельный Compose-проект `signalis-demo-20261113`, порт 18096 и новые тома. Не запускайте на нём разрушающие тесты.

## Подготовка до выступления

Из корня комплекта в PowerShell:

```powershell
$env:APP_PORT='18096'
docker compose -p signalis-demo-20261113 up --build -d
docker compose -p signalis-demo-20261113 exec api python -m app.manage create-admin
```

Создайте собственные реквизиты. Откройте `http://localhost:18096`. Дождитесь готовности базы знаний в «Источниках». Первой сборке нужен интернет; загрузку модели завершите до выступления. Не обещайте запуск без сети, если он не подтверждён в финальном отчёте.
Проверьте «Аварийные события», дождитесь PostgreSQL. Ничего не удаляйте из исходного корпуса.

## Сценарий

1. **0:00–0:45.** Войти. «Источники»: показать настоящий Prometheus, время опроса и готовность поиска. Включить «Аварийные события», подождать до 30 секунд.
2. **0:45–1:30.** «События»: открыть PostgreSQL. Показать автоматические тип, категорию, P1, источник и рекомендации. Объяснить: это помощь инженеру, команды на инфраструктуре не исполняются.
3. **1:30–2:30.** «Исправить классификацию»: warning / database / P2, комментарий «Учебная оценка инженера». Сохранить. Показать отметку, автора и время. Закрыть карточку, проверить фильтр warning/P2 и сводку. Снять фильтры, обновить страницу: правка остаётся. Повторно изменить комментарий: запись обновляется, история сохраняется.
4. **2:30–3:30.** Открыть рекомендацию. Прочитать фактические общие слова; сходство — близость текстов, не вероятность правильности и не обоснование каждого действия. Нажать «Помогла», повторить, затем «Не помогла». Открыть «Базу знаний»: счётчики соответствуют последней оценке, повтор не прибавляет голос.
5. **3:30–4:30.** «Журнал действий»: показать исправление и обе смены оценки с автором и временем. В карточке показать историю эпизода. При необходимости «Принято к ручному выполнению»: пояснить, что действие вне приложения инженер выполняет самостоятельно.
6. **4:30–5:30.** Терминал: экспорт одной командой, затем пересчёт метрик:

```powershell
docker compose -p signalis-demo-20261113 exec -T api python scripts/export_corrections.py --output /data/uploads/corrections.json
docker compose -p signalis-demo-20261113 exec -T api python scripts/evaluate.py --dataset /data/uploads/corrections.json --output /data/uploads/corrections-metrics.json
docker compose -p signalis-demo-20261113 cp api:/data/uploads/corrections.json ./corrections.json
```

На намеренно изменённом примере метрики могут быть низкими, код 1 означает результат ниже 90%, а не поломку экспорта. Оценивается автоматический классификатор относительно инженера. Корпус исправлений содержит выбранные ошибки, а не случайную выборку; дообучение автоматически не запускается.
7. **5:30–6:30.** Показать загрузку `examples/reviewer-queue.json`, задание очереди и найденную инструкцию. Завершить ограничениями: текстовые документы, отсутствие OCR и автоматического выполнения, учебный размер корпуса.

## Вероятные вопросы жюри

- **Где ИИ?** TF-IDF + Logistic Regression для текста событий вместе с метками и правилами. Для инструкций — FastEmbed, мультиязычный MiniLM в ONNX, 384 измерения и cosine search pgvector. Облачного генеративного LLM нет.
- **Почему нельзя гарантировать 90% на наших событиях?** Авторский проверочный корпус мал и отделён от обучения; неизвестный независимый набор не измерен. Исправления инженеров дают отдельный корпус, смещённый в сторону ошибок.
- **Почему выбран регламент?** Векторный поиск находит близкий фрагмент; отдельно показаны общие нормализованные слова события и условия. Это не причинное объяснение внутреннего решения модели.
- **Как хранятся исправления?** Одна актуальная запись на эпизод, снимок входа, автор, время; изменения и аудит атомарны. Новый эпизод не наследует правку.
- **Как считаются голоса?** Инженер + эпизод + ID регламента + редакция. Повтор идемпотентен; смена заменяет голос. Исторический снимок переживает удаление живой инструкции. Каталог суммирует все редакции существующего регламента.
- **Что защищает от запоздавшего запроса?** Backend проверяет редакцию и поколение рекомендаций под блокировкой эпизода; frontend отбрасывает устаревшие ответы после локальной записи.
- **Система сама перезапустит БД?** Нет. Подтверждение меняет журнал ручной работы; исполнительного слоя нет.
