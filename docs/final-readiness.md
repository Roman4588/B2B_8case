## Исправления этой приёмки

1. `operator.spec.ts` создаёт новый эпизод настоящим циклом Prometheus normal/outage, обязательно выполняет ручное действие и проверяет уникальный комментарий в истории и аудите. Старые принятые события больше не подменяют действие текущего прогона.
2. `feedback-live.spec.ts` создаёт и индексирует собственный регламент, оценивает и удаляет его по ID. Исходные инструкции больше не расходуются повторными прогонами. Число seed-регламентов контролируется отдельно.
3. `Incidents.tsx` не применяет запоздавшую оценку поверх более новой оценки той же редакции/поколения. Регрессия сначала воспроизведена в настоящем браузере (старое «Помогла» заменяло новое «Не помогла»), затем закрыта проверкой времени сохранения.
4. README отделяет текущий локальный комплект от прежнего публичного стенда и скачивания `main`. Команды, интернет-зависимости, сценарий демонстрации, матрица и состав передачи актуализированы.

Согласованный дизайн, функции и доработки других чатов сохранены. Редизайн, построение графа, пентест, создание видео, массовый рефакторинг и обновление стека не проводились. Подтверждённых проблем читаемости/адаптивности, требующих нового применения Impeccable, не найдено.

## Воспроизведение проверяющим

Распакуйте переданный комплект и откройте PowerShell **в его корне**. Не заменяйте его прежним `git clone main`.

```powershell
$env:APP_PORT='18095'
docker compose -p signalis-final-20261112 up --build -d
docker compose -p signalis-final-20261112 exec api python -m app.manage create-admin
```

Создайте собственный email/пароль. Откройте `http://localhost:18095`, войдите, дождитесь готовности базы знаний и мониторинга в «Источниках». На новой машине требуется интернет. Повторный запуск: та же команда up; остановка с сохранением данных: `docker compose -p signalis-final-20261112 down` (без `-v`).

Для полного backend используйте отдельную тестовую базу. Команда CREATE DATABASE нужна один раз для нового QA-проекта; не направляйте проверки на рабочую базу. Здесь используется стандартный локальный пароль Compose.

```powershell
docker compose -p signalis-final-20261112 exec -T db psql -U copilot -d copilot -c 'CREATE DATABASE acceptance_test'
docker compose -p signalis-final-20261112 exec -T -e DATABASE_URL=postgresql+psycopg://copilot:copilot-local@db:5432/acceptance_test api python -m app.bootstrap
docker compose -p signalis-final-20261112 --profile test run --build --rm -e DATABASE_URL=postgresql+psycopg://copilot:copilot-local@db:5432/acceptance_test tests
```

После завершения backend, из `frontend`:

```powershell
npm ci
npm run build
npx playwright install chromium
$env:BASE_URL='http://localhost:18095'
$env:E2E_EMAIL='ВАШ_ТЕСТОВЫЙ_EMAIL'
$env:E2E_PASSWORD='ВАШ_ТЕСТОВЫЙ_ПАРОЛЬ'
# Если используете установленный Edge: $env:PLAYWRIGHT_CHANNEL='msedge'
npm run test:e2e
npm run test:e2e
```

Не запускайте тяжёлые backend-тесты одновременно с браузерной приёмкой. Браузерные live-сценарии создают собственные инструкции; демо проводите на отдельном проекте из `demo-script.md`.

Проверка PDF60 из корня, после установки `backend/requirements-dev.txt`: задайте E2E_EMAIL/E2E_PASSWORD и выполните `python scripts/smoke.py --url http://localhost:18095 --output outputs/smoke.json`.
Дополнительный сценарий ролей/редактирования/ошибки очереди выполняется внутри тестового образа с доступом к его uploads. Он исправляет только созданный им тестовый файл, имитируя устранение причины ошибки хранения/содержимого; это не функция редактирования загрузки через UI.

```powershell
$env:E2E_EMAIL='ВАШ_ТЕСТОВЫЙ_EMAIL'
$env:E2E_PASSWORD='ВАШ_ТЕСТОВЫЙ_ПАРОЛЬ'
docker compose -p signalis-final-20261112 --profile test run --rm -v "${PWD}/scripts:/checks:ro" -e PYTHONPATH=/app -e E2E_EMAIL -e E2E_PASSWORD tests python /checks/acceptance_extra.py
```

Экспорт и пересчёт — две команды README, без переноса данных в training.json. Для стенда этой приёмки добавляйте `-p signalis-final-20261112` после compose. Файл выгрузки расположен в томе uploads; `docker compose ... cp` переносит его на хост.
