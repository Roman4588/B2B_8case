## Исправления

- `backend/app/advice.py`: отдельная осторожная политика рекомендаций. Явно завершённая проверка при info/P4 без сомнений и признаков проблемы получает not_required. Отрицательные, смешанные, неопределённые сообщения и остальные P4 продолжают поиск. Это не переобучение классификатора.
- `recommendations.py` и `main.py`: такая проверка не запускает аварийный поиск; ранее сохранённый ошибочный совет также не показывается. Ручная классификация, изменившая применимость советов, обновляет их поколение. Оценить скрытую устаревшую рекомендацию нельзя.
- `Incidents.tsx`: различаются «Вмешательство не требуется», «Регламент не найден» и история снятого события. Снятое событие не обещает продолжающийся поиск.
- `Knowledge.tsx`: поиск выполняется при отправке формы; повторное нажатие «Найти» работает. Счётчики обновляются через защищённый GET /api/runbooks/usefulness без модели и очереди. Удалённые, изменённые или ещё не готовые инструкции скрываются из старого снимка выдачи с предложением повторить поиск. Новые документы попадают в результаты после нового поиска.

## Проверки

Новые проверки сначала воспроизвели дефекты. Намеренная инверсия проверки противоречий в отдельной копии модуля приводит к падению обеих положительных регрессий; рабочий исходник не менялся.

На итоговых исходниках прошли 116 обычных backend-тестов, 4 PostgreSQL-проверки конкурентности/миграции/сохранности A/B, сборка frontend и 18 затронутых браузерных сценариев, включая обновлённые заглушки API и прежние проверки интерфейса. Полный CI выполняется после отправки коммита; его итог и опубликованный SHA фиксируются в протоколе доставки.

Отдельный локальный стенд с синтетическими событиями, десятью исходными регламентами, настоящими PostgreSQL/pgvector и моделью:

| Случай | Наблюдение |
|---|---|
| Успешная проверка | Нет аварийных инструкций; «Вмешательство не требуется». |
| Отказ PostgreSQL | Первым «Отказ PostgreSQL», сходство 0,9141; ниже другая инструкция о репликации. |
| Заполнение диска | Первым «Заканчивается место на диске», сходство 0,6839; ниже другая инструкция о памяти. Дублей нет. |
| Нет близкого регламента | «Регламент не найден». |
| Задачи A/B | Классификация и оценка сохраняются; автоматическая классификация остаётся доступной; аудит содержит обе записи. |

Ровно одна карточка не следует из проблемы дублей: разные похожие инструкции допустимы. Порог поиска не менялся. Сходство не является вероятностью правильности.

После исправления за 16 секунд отправлен один семантический запрос и четыре запроса метаданных. В SEARCH_IN_WORKER за тот же интервал подтверждены одна принятая и одна завершённая задача semantic_search. Число обращений к модели до исправления отдельно не инструментировалось: четыре HTTP-запроса и путь до embed подтверждены раздельно.

## Отложенные решения и ограничения

Облачные документы, оценки и история не очищались. Для демонстрации достаточно отдельного согласованного набора без повторных импортов. Фильтрация по test/demo ненадёжна. Объединение по заголовку смешивает разные шаги и редакции; объединение по содержимому требует решения об ID, оценках, ссылках и удалении одного из импортов. Предупреждение о повторном файле полезно, но не исправляет уже загрязнённую выдачу.

Для общей квоты нужны бюджет с учётом моделей/БД, предел ожидания, атомарное резервирование при параллельных загрузках и восстановление после сбоев. Это не обязательно требует новой схемы, но не сводится к проверке «посчитать и записать». Отказавшие импорты сохраняют файл для повтора. Удаление импорта освобождает исходник; удаление одной инструкции сохраняет документ. Неуспех очистки отражается в ответе. Осиротевшие при сбоях файлы требуют отдельного решения.

Прежние замечания Ruff о порядке импортов в тестах и предупреждения сборщика lucide-react не скрывались; несвязанные файлы и зависимости не менялись. Нагрузочные гарантии и универсальное понимание произвольного текста не заявляются.

## Доставка и откат

Используются существующие GitHub main и Git Amvera master приложения madaminchyk/b2b. Standalone, постоянный /data, переменные, домен и тариф сохраняются. Миграций в исправлениях нет; прежняя проверяемая резервная копия перед изменением схемы остаётся обязательной. Откат кода — отдельный revert-коммит с сохранением схемы 0004 и рабочих данных. Данные БД автоматически не откатываются.
