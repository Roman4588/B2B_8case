## Что улучшить без расширения объёма проекта
1. Импорт повествовательного Markdown: parse_runbooks разделяет документ по заголовкам. Наш файл «Маяк» дал восемь инструкций, в том числе отдельные «Ограничения» и «Контрольная фраза». Лучше сохранять цельный регламент, шаги и предостережения. До исправления использовать компактные примеры JSON или явные правила «Если → действие».
2. Запуск: проверять доступность Docker Engine до сборки, выводить понятный статус и ожидать готовности модели. Наличие команды docker ещё не означает, что Docker Desktop работает.
3. Убрать неоднозначность статуса: отдельно показывать готовность API, модели и мониторинга.
4. Увеличить независимый проверочный набор: незнакомые формулировки, неоднозначные события, отрицания, события без labels и случаи, когда релевантного регламента нет. Не выдавать 100% на 48 учебных примерах за общую точность.
5. Удалять шумовые примеры перед записью финального видео; тестирование проводить на отдельном демонстрационном стенде.

## Как упростить проверку жюри
Рекомендуемый комплект: ссылка на конкретный release/commit, короткий README, видео ≤5 минут, один понятный тестовый JSON и сценарий на 5–7 минут. Готовый образ backend/frontend с тегом релиза уменьшит время сборки; подготовка модели заранее устранит ожидание первой загрузки. Отдельно сохранить воспроизводимый исходный Compose. Эти улучшения предложены, но не реализованы этим аудитом.

Сценарий проверки:
1. Открыть рабочий стенд и войти в выделенный демонстрационный аккаунт либо создать локального администратора одной указанной командой.
2. «Источники»: увидеть Prometheus online; включить учебные аварии.
3. «События»: открыть критический инцидент, показать категорию, приоритет, объяснение и источник инструкции.
4. Принять к ручному выполнению, затем отметить выполнение; открыть запись журнала. Подчеркнуть, что инфраструктурные команды система не запускает.
5. Загрузить небольшой JSON «Если X → Y», дождаться готовности, найти его перефразированным запросом.
6. Показать обработку большого PDF и сохранённые результаты тестов.
7. Переключить восстановление и показать изменение состояния мониторинга.
