# Архитектура и границы ответственности

## Получение события

Celery Beat ставит опрос Prometheus в очередь каждые 15 секунд. Worker читает официальный
`/api/v1/alerts`, проверяет успешность ответа и нормализует firing alerts.
Стабильный SHA-256 от отсортированных labels и имя источника образуют ключ дедупликации.
Сначала проверяется весь снимок, затем сохраняется новое состояние.
Неудачный запрос не считается пустым снимком и не закрывает инциденты.

Классификатор использует разрешённые severity/category из мониторинга, затем предметные
правила и отдельную TF-IDF + Logistic Regression модель. Произвольные метки priority
не принимаются. Приоритет определяется опубликованной политикой. Низкая уверенность
выделяется как необходимость ручной проверки.

## Регламенты и поиск

API сохраняет загруженный файл под UUID в общем томе и создаёт устойчивую запись задания.
Ответ HTTP 202 возвращается до извлечения текста. Очередь обслуживает JSON/MD/TXT/PDF/DOCX;
прогресс хранится в PostgreSQL, поэтому закрытие браузера не прекращает обработку.
Повтор задания использует уникальные ключи `(job_id, index)`.

FastEmbed вычисляет 384-мерные векторы компактной многоязычной ONNX-моделью.
Фрагменты сохраняются в колонке pgvector. Поиск использует cosine distance в самой БД,
группирует результаты по регламентам и исключает слабые совпадения.
В пользовательский ответ попадают сохранённые шаги, а не сгенерированные команды.

Вычисление эмбеддингов не удерживает блокировку редактирования. Перед публикацией
worker блокирует строку регламента, повторно проверяет revision и атомарно заменяет
векторы. Если инструкция изменилась, старая версия не публикуется как готовая.
Готовая новая инструкция помечает рекомендации активных инцидентов для пересчёта.

## Ручная работа

Аутентифицированный инженер может принять, завершить или отклонить рекомендацию.
Переходы состояния сериализуются блокировкой строки события. Повтор одного действия
не создаёт повторный аудит. Данные о восстановлении мониторинга и ручном выполнении
не смешиваются: нажатие «Выполнено вручную» не подделывает состояние Prometheus.

Исполнительного слоя нет. В коде нет SSH, вызова shell из API, обращения к remediation API,
автоматического перезапуска служб или изменения сетевых правил.
Учебный экспортёр изменяет только числовые синтетические метрики по явному запросу
пользователя, а не управляет какой-либо инфраструктурой.

## Надёжность и ограничения

- PostgreSQL хранит профиль, сессии, события, фрагменты, задания и журнал.
- Redis использует AOF; очередь принимает JSON. Задания идемпотентны.
- Прерванные running imports после 15 минут без прогресса возвращаются в очередь.
- Учётная запись имеет PBKDF2-хэш пароля; cookie HttpOnly/SameSite и проверку Origin для записей.
- API, worker, Redis и БД доступны только в сети Compose; наружу публикуется Nginx на loopback.
- Приложение не требует облачной регистрации. При первой загрузке контейнеров/модели нужен интернет.
- База знаний не заменяет проверку инженером. Незнакомые события могут потребовать уточнения.
- Авторский тестовый набор не доказывает точность на неизвестных логах организаторов.
- PDF без текстового слоя нужно предварительно распознать.
- Первая миграция фиксирует исходную схему приложения; последующие изменения нужно оформлять новыми ревизиями Alembic.
